# 開発メモ

## セットアップ

Node.js 18以降とPython 3があれば動きます。外部からダウンロードするものはありません。

```bash
npm install        # tools/stubs/ をリンクするだけ（ネットワーク不要）
npm test           # check + simulate
npm run build      # dist/*.mcaddon, dist/*.mcpack
```

## テスト用スタブ

`npm run check` と `npm run simulate` は `@minecraft/server` / `@minecraft/server-ui` の
最小スタブに対してスクリプトを**実際にロード**します。スタブは `tools/stubs/` にあり、
`package.json` の `devDependencies` から `file:` 参照されています。

実物のAPIとは挙動が違うので、**スタブが通ることは動作保証ではありません**。
あくまで「import 漏れ・タイポ・エクスポート名の不一致」を潰すためのものです。
詳細は [tools/stubs/README.md](../tools/stubs/README.md) を参照してください。

## テストが見ているもの

### `tools/check.mjs`（静的チェック）

- すべてのJSONがパースできる
- すべてのスクリプトがロードできる（import/exportの整合）
- BPがRPのUUIDに依存している／UUIDが重複していない
- BPとRPのエンティティ識別子が一致している（`pvp:bot`）
- 見た目がバニラのプレイヤーモデル・スティーブテクスチャを指している
- `enable_attachables` が有効（これが無いと防具が見えない）
- レンダーコントローラ・アイテムアイコン・ルートテーブル・pack_iconが実在する
- レベル表が単調（レベルを上げたら弱くなる項目が無い）

### 握り潰した例外の可視化

`safe()` は例外を握り潰します。エンティティがティック中に無効化されるのは異常ではないので
これ自体は必要なのですが、**無音で握り潰していたことがこのアドオンの全バグの共通原因**でした。
症状はいつも「なぜか動かない」で、理由がどこにも残っていませんでした。

いまは握り潰した回数とメッセージを記録し、

- `!pvp diag` の `suppressed errors` 行
- `npm run simulate` の統合テスト（**0でなければ失敗**）

の両方から見えます。

### `tools/simulate.mjs`（挙動シミュレーション）

偽のディメンションと簡易物理の上で本物の `BotBrain` を毎ティック回します。
`combat.js` がクリティカル時に出すパーティクルを数えることで、
本番コードに計測用の細工を入れずにクリティカル率を測っています。

検証している性質:

| 検証 | 意図 |
|---|---|
| 全レベルが命中する | AIが完全に停止していないこと |
| Lv5のDPSがLv1を大きく上回る | レベル差が体感できる大きさであること |
| DPSがレベルで逆転しない | 中間レベルが飛び抜けたり凹んだりしない |
| どのレベルも 2.00 hits/s を超えない | **無敵時間を貫通していない**（最重要） |
| Lv5が逃げる相手を追い続けられる | 追跡時にストレイフで自滅していない |
| Lv1のクリティカル率が0%付近 | 初心者らしさ |
| Lv5のクリティカル率が60%超 | ジャンプクリティカルのタイミングが機能している |
| 弓の誤差がレベルで縮む | 偏差射撃・重力補正が効いている |
| 高レベルほどフルチャージで撃つ | 引き切らずに連射する下手さが再現できている |
| ジャンプ頂点がバニラ値 1.2522 と一致 | 接地時の残留速度を打ち消せている（1ブロック越えられるか） |
| 知覚遅延がレベルで単調に縮み、毎回ばらつく | 反応時間が固定値やゼロになっていない |
| 最速レベルでも80ms以上 | 人間より速く反応していない |
| 同一レベル2体が同時に振らない・鏡像に動かない | 6ペアの平均で判定（1ペアだと乱数の引き次第で大きく振れる） |
| 設置は無支持で拒否・1回1個・対象を向く | サバイバルの設置ルール |
| `minecraft:equippable` **無し**でも装備・設置・食事・持ち直しが動く | フォールバック経路（実機はこちらの可能性が高い） |
| 生成→被弾→死亡→リスポーン→撤去が動く | マネージャのイベント配線（ティック処理以外） |
| 60秒の実戦で内部例外0件 | 握り潰された失敗がない |

## パックJSONにコメントを書かないこと

Minecraftはパック内のJSONをスキーマ検証していて、**知らないキーを拒否します**。
慣習的に使われる `"//": "説明"` も例外ではなく、

- ビヘイビアーパックの `components` 直下 → `[Log][warning] ... not present in the Schema`
- クライアントエンティティの `description` 直下 → `[Animation][error] child '//' not valid here.`

となります。後者はエラーなので見た目が壊れる可能性があります。
`npm run check` はパックJSON内の `//` で始まるキーを**すべて検出して失敗させます**。

そのため、エンティティ定義の設計意図はJSONではなくここに書いてあります。

### `entities/pvp_bot.json` の設計意図

| 記述 | 理由 |
|---|---|
| `collision_box` 0.6 × 1.8 | プレイヤーと同一の当たり判定 |
| `movement` 0.1 / `jump.static` 0.42 | バニラのプレイヤー値。実際の移動はスクリプトが上書きするが、物理の土台として合わせておく |
| `attack` damage **0** | バニラのモブ攻撃を無効化し、近接判定を `scripts/combat.js` に一本化するため。これをしないと無敵時間もダメージ式もモブ準拠になる |
| `minecraft:equippable` を**書かない** | これはラマの絨毯・馬の鞍用の相互作用コンポーネントで、防具スロットとは無関係。宣言すると装備が一切付かなくなる。人型Mobは最初から防具スロットを持っている（`npm run check` が再混入を拒否する） |
| `equipment` 空テーブル | 装備を持ちうるエンティティであることを明示する。中身はスクリプトが入れる |
| `inventory` 36スロット `private` | ブロック・矢・金リンゴを本当に消費させるため。`private` でプレイヤーが開けないようにする |
| `loot` 空テーブル / `experience_reward` 0 | 練習台なので装備をばら撒かない |
| `persistent` | 離れても消えない |
| `behavior.float` だけ残す | 水に浮く挙動はバニラAIのほうが自然。それ以外のAIを入れるとスクリプトの移動制御と競合する |

## チューニング

数値はすべて `packs/PvPPracticeBP/scripts/config.js` にあります。
いじったら `npm test` を回してください。単調性チェックと挙動チェックの両方が走ります。

パラメータの意味は [LEVELS.md](LEVELS.md) を参照してください。

## ゲーム内での確認

`dist/PvPPractice.mcaddon` を開いてワールドに適用し、`!pvp spawn 5 netherite` で
最高レベルのボットを呼び出すのが一番速い確認方法です。

スクリプトのエラーはゲーム内のコンテンツログに出ます。
設定 → クリエイター → 「コンテンツログをGUIに表示」をONにしてください。
