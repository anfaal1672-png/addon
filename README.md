# PvP練習アドオン（マイクラ統合版）

見た目が**完全にデフォルトのスティーブ**のPvPボットを追加するアドオンです。
ボットは防具を着て、剣で殴り、弓を射って、ブロックを置きます。体力もリーチも移動速度も、
サバイバルのプレイヤーと**まったく同じ数値**で戦います。

強さは**5段階**。レベル1は「今日はじめて剣を持った人」、レベル5は「1ティックも無駄にしない世界最高峰」です。

---

## 何が「プレイヤーと同じ」なのか

| 項目 | ボットの仕様 |
|---|---|
| 見た目 | バニラの `geometry.humanoid.custom` + `textures/entity/steve`、スケール 0.9375。プレイヤーと同じモデル・同じテクスチャ・同じ大きさ |
| 当たり判定 | 0.6 × 1.8（プレイヤーと同一） |
| 体力 | 20（ハート10個）。回復もダメージも通常どおり |
| 移動速度 | 歩き 4.317 m/s、ダッシュ 5.612 m/s、ジャンプ力 0.42（すべてバニラ準拠） |
| リーチ | 最大 3.0 ブロック |
| 防具 | 頭・胴・脚・足の4スロットに本物の防具を装備。防護（Protection）も耐久も効く |
| 武器 | 素手/剣/斧/トライデントの実ダメージ表 + ダメージ増加（+1.25/レベル） |
| クリティカル | 落下中に当てると1.5倍。統合版と同じく**ダッシュ中でもクリティカルは出る** |
| 無敵時間 | 被弾後10ティック。スクリプトダメージでもこれを**貫通しない** |
| 弓 | 本物の `minecraft:arrow` を発射。所有者はボット。防具・飛び道具耐性も正しく効く |
| ブロック | 自分のインベントリにあるブロックしか置けない。置いた分だけ減る |
| 落下・溺水・溶岩 | すべてプレイヤーと同じように食らう |
| ドロップ | なし（練習台なので装備を撒き散らさない） |

ボットに有利な補正は一切入っていません。差がつくのは**プレイの上手さだけ**です。

## 導入

### かんたん導入（ビルド済みファイルを使う）

```bash
npm run build
```

`dist/PvPPractice.mcaddon` ができるので、これをMinecraftで開く（タップ/ダブルクリック）だけです。
ワールド設定でビヘイビアーパックとリソースパックの両方を有効化してください。

### 手動導入

`packs/PvPPracticeBP` を `behavior_packs` に、`packs/PvPPracticeRP` を `resource_packs` にコピーします。

### 必須設定

- **Minecraft統合版 1.21.80 以降**
- ワールド設定で **「ベータAPI」を有効にする必要は__ありません__**（安定版のScript APIのみ使用）
- ワールド設定の **「アドオンを使用する」** はON

## 使い方

初参加時に **PvPリモコン** が配布されます。持って使う（長押し/右クリック）とメニューが開きます。

- **ボットを召喚** — レベル・キット・数・距離を選ぶ
- **クイック召喚** — 前回と同じ設定でもう一度
- **ボットを管理** — 個別にレベル変更・全回復・リスポーン地点設定・装備変更・削除
- **戦績** — 与ダメ／被ダメ／ダメージ比／撃破・デス／最大コンボ
- **設定** — 下記参照

リモコンを失くしたら `!pvp remote` で再取得できます。

### チャットコマンド

```
!pvp                       メニューを開く
!pvp spawn <1-5> [キット] [数]   ボットを召喚      例: !pvp spawn 5 netherite 2
!pvp clear                 ボットを全削除
!pvp level <1-5>           近くのボットのレベル変更
!pvp kit <キット名>         近くのボットの装備変更
!pvp stats                 戦績を開く
!pvp remote                リモコンをもらう
!pvp diag                  動作診断（下記）
!pvp help                  ヘルプ
```

### `!pvp diag` — 動作診断

「防具を着ていない」「殴るモーションが出ない」といった症状は原因が複数あり得て、
アドオン側からは外見だけでは区別できません。そこで実行時に自己診断して結果を表示します。

```
=== PvP Practice diagnostics ===
✔ equip.component  setEquipment works (enchantments supported)
✔ anim.properties  entity properties drive the vanilla swing/eat animations
✔ inventory.component  container available
Nearest bot Lv5 kit=netherite
  head minecraft:netherite_helmet
  chest minecraft:netherite_chestplate
  ...
animation properties swing_id=7 using=0
inventory 4 stacks
state sprint=true bodyYaw=134 aimYaw=98
```

うまく動かないときはこの出力をそのまま報告してもらえれば原因が特定できます。

1.21.80以降のスラッシュコマンドが使える環境では `/pvp:spawn`, `/pvp:clearbots`,
`/pvp:level`, `/pvp:menu` も自動で登録されます（使えない環境では `!pvp` だけが動きます）。

> スラッシュコマンド側だけ `clearbots` という名前なのは、`clear` という短縮名がバニラの
> `/clear` に予約されていて、そのまま使うとコンテンツログに衝突警告が出るためです。
> チャットコマンドの `!pvp clear` はそのまま使えます。

### レベル5が実際にやってくること

- **無敵時間ぴったりに殴る**。統合版は被弾後10ティック無敵なので、連打しても意味がない。
  Lv5は無敵が切れる瞬間だけ殴るのでDPSが理論値になる
- **ジャンプ→落下中にクリティカル**を毎回きれいに当てる
- **Wタップ**（当てた直後にダッシュを切って踏み直す）でノックバックを最大化する
- ノックバックで飛ばされた相手を**距離を詰めて追撃**する（コンボ）
- 自分が飛ばされたときは**逆方向に入力して受けるノックバックを相殺**する
- 弓は**相手の移動速度と矢の落下を計算した偏差射撃**。30ブロック先の横移動にも当ててくる
- 飛んできた矢を**察知して横に跳ぶ**
- 追い詰められたら**ブロックで壁を作ってから**金リンゴを食べる
- 削られたらタワーで逃げる、穴があれば橋をかける、落下死しそうなら**MLG水バケツ**

## 技術メモ

### 見た目が完全にスティーブになる仕組み

リソースパックには**画像を一切同梱していません**。クライアントエンティティ定義が
バニラのアセットを直接指しています。

```json
"textures":  { "default": "textures/entity/steve" },
"geometry":  { "default": "geometry.humanoid.custom" },
"scripts":   { "scale": "0.9375" },
"enable_attachables": true
```

`geometry.humanoid.custom` はバニラの `minecraft:player` が使っているモデルそのもの、
`0.9375` はバニラがプレイヤーに掛けているスケールそのものです。
統合版では防具と手持ちアイテムは**アタッチャブル**として描画されるため、
`enable_attachables: true` を入れるだけでプレイヤーとまったく同じ位置に防具が乗ります。

### 防具が装備される仕組み（ハマりどころ）

**`minecraft:equippable` は防具のコンポーネントではありません。** これはラマの絨毯や馬の鞍のように
「プレイヤーが触って装備させる」ための相互作用コンポーネントで、バニラのゾンビにもスケルトンにも
**存在しません**。これを防具スロットのつもりで宣言すると、装備が一切付かなくなります。

正しくは、人型Mobは最初から防具スロットを持っており、スクリプト側の
`EntityEquippableComponent` でそこへ直接アイテムを入れます。
`kits.js` はこれを試したうえで**入ったかどうかを読み返して確認**し、
だめなら `/replaceitem` にフォールバックします。どちらの経路が使われたかは `!pvp diag` に出ます
（`/replaceitem` 経路ではエンチャントが付きません）。

### 殴る・食べるモーションの仕組み

バニラのアニメーションコントローラはこう定義されています。

```
controller.animation.humanoid.attack             variable.attack_time >= 0 の間だけ再生
controller.animation.humanoid.use_item_progress  variable.use_item_startup_progress > 0 の間だけ再生
```

これらの変数は通常エンジンが設定しますが、スクリプトからMolang変数は書けません。
代わりに**エンティティプロパティ**を書き、リソースパックの `pre_animation` でMolang変数へ橋渡ししています。

```json
"v.swing_id = q.property('pvp:swing_id');",
"(v.swing_id != v.last_swing_id) ? { v.last_swing_id = v.swing_id; v.swing_start = q.life_time; };",
"v.attack_time = (v.swing_elapsed >= 0.0 && v.swing_elapsed < 0.3) ? ... : -1.0;"
```

プロパティは「振った回数のID」で、経過時間はクライアント側が `query.life_time` から計算します。
毎ティック同期する必要がなく、**1回の攻撃につきプロパティ書き込み1回**で済みます。

再生されるのは自作アニメーションではなく**バニラのプレイヤーと同じアニメーション**なので、
振り方も食べ方もプレイヤーと完全に一致します。

### 体と頭が別々に回る仕組み

`Entity.setRotation` の `y` は**頭ではなく体の向き**です（Microsoft公式ドキュメントに明記）。
毎ティックこれを相手方向へ向けると胴体ごとスナップして回り、一目で人間でないと分かります。

そこで、

- **体の向き** = 移動方向（`setRotation`）。頭との差が50°を超えたときだけ追従する
- **頭の向き** = ビヘイビアパックの `minecraft:behavior.look_at_player` に任せる
- **狙いの向き** = ブレインが内部に持つ値（当たり判定・弓の計算に使用）

の3つを分離しています。

### 戦闘がスクリプト側にある理由

エンティティ定義の `minecraft:attack` は **damage 0** にしてあります。
バニラのモブ攻撃はリーチも間隔もモブ用の挙動なので、代わりに `scripts/combat.js` が
毎回の攻撃を解決しています。こうすることで

- 武器のダメージ表・ダメージ増加・クリティカル倍率がプレイヤーと同じ式になる
- **10ティックの無敵時間を尊重できる**（`applyDamage` は本来これを無視してしまう）
- CPS・Wタップ・ノックバックをレベルごとに正確に作り分けられる

移動も同様で、バニラAIは `behavior.float`（水に浮く）とターゲット取得・頭の追従だけ残し、
それ以外は `scripts/movement.js` が毎ティック速度を**加速度制限つきで**書き換えています。

この加速度制限が重要です。速度を毎ティック上書きすると、**空中でノックバックが止まります**。
プレイヤーにできない挙動で、最大の違和感になります。バニラは加速度モデルなので、

- 地上: 最大 0.16 ブロック/ティックまで変化（摩擦が支配的なので実質すぐ最高速）
- 空中: 最大 0.022 ブロック/ティックまで（プレイヤーの空中制御はこの程度しかない）

としています。空中制御の効き具合はレベルの `kbControl` でさらに絞られるので、
下手なボットは吹き飛ばされたら最後まで飛んでいきます。

### 開発

```bash
npm install        # tools/stubs/ をリンクするだけ（ネットワーク不要）
npm test           # check + simulate をまとめて実行
npm run check      # JSON検証 + 全スクリプトのロード + 相互参照チェック
npm run simulate   # ヘッドレス決闘シミュレーション（下記）
npm run textures   # pack_icon.png とアイテムアイコンを再生成
npm run build      # dist/ に .mcaddon と .mcpack を出力
```

`npm run check` は `@minecraft/server` のスタブを使って全モジュールを実際に読み込むので、
import のタイプミスやエクスポート漏れをゲームを起動せずに検出できます。

### レベル差の検証（シミュレーション）

`npm run simulate` は本物の `BotBrain` を偽の物理世界で30秒ぶん動かし、
レベルごとの性能を測ります。ゲームを起動せずに「レベルを上げたら本当に強くなっているか」を確認できます。

```
静止した相手（30秒・ダイヤ装備）
  Lv   DPS    hits/s  crit%  engaged  closest
  1    4.90    0.70     0%      97%    0.51
  2    9.57    1.27    16%      97%    0.77
  3   15.40    1.60    75%      97%    1.04
  4   18.43    1.77    98%      97%    1.32
  5   20.18    1.93    98%      96%    1.60

逃げる相手（30秒）
  Lv   DPS    hits/s  crit%  engaged  closest
  1    4.67    0.67     0%      22%    2.70
  5   18.08    1.73    98%      87%    1.96

20ブロック先で横移動する相手への弓（30秒）
  Lv   shots  shots/s  mean aim error  mean draw
  1      22     0.73       4.55°        60%
  5      21     0.70       0.11°       100%
```

見どころは **hits/s** の列です。統合版の無敵時間が10ティックなので理論上限は
**2.00 hits/s**。レベル5の 1.93 はほぼ理論値、つまり無敵時間中の空振りがほぼゼロだということです。
レベル1は 0.70 しかなく、CPSは足りているのに無敵時間に殴り続けて損をしています。
弓も同様で、レベル5は毎回フルチャージ（100%）で撃ち、レベル1は引き切る前に離してしまいます（60%）。

このシミュレータは開発中に実際に2つのバグを見つけています
（高レベルほど逃げる相手を追えなくなる／ジャンプクリティカルのタイミングが噛み合っていない）。

### プレイヤーとの一致のために入れている細かい処理

見た目と挙動の「らしさ」は細部の積み重ねなので、意図が分かるように列挙しておきます。

| 処理 | 入れていない場合に起きること |
|---|---|
| アニメーションは `animation.player.*` を使用 | `humanoid`（ゾンビ系）は歩き方も振り方も微妙に別物 |
| 間合い外でも連打で空振りする | 腕が動く距離＝リーチだと一目で分かる |
| 空振り間隔をランダム化 | 固定周期のクリックは機械的。複数体だと完全に同期する |
| ボットごとに位相と無敵時間読みの誤差を持たせる | 同じコードが同じティックに同じ判断をして、2体が1体の複製に見える |
| ブロック設置時に持ち替えて腕を振る | 何も持たずに無言でブロックが湧く |
| 隣接面が無い位置には置けない | 空中にブロックが出現する |
| 設置は1回1個・4ティック間隔 | 壁が一瞬で2段生える（プレイヤーには不可能） |
| 置く瞬間そのブロックを向く | あさっての方向を見たまま壁を作る |
| 金リンゴを手に持ち32ティック掛けて食べ、食べ終わってから効果 | 一瞬で回復する。中断してもリンゴが減らないのも本来の仕様 |
| アイテム使用中は移動速度を30%に | 弓を引きながら全速で動くのは不可能 |
| 撤退時は体ごと反転してダッシュ | 狙い方向±50°の制限のせいで後ろ歩きになる |
| 壁に阻まれたら横に回り込む | 壁に向かって歩き続ける |
| 被弾・死亡時にプレイヤーの声を再生 | カスタムエンティティは音イベントを持たないので無音 |
| 武器と防具の耐久が減り、壊れる | スクリプトのダメージにエンジンは耐久を課さない |
| ファイアアスペクトを手動適用 | スクリプトダメージにはエンチャント効果が乗らない |
| ネームプレートを深度テスト無効・遠距離表示に | Mobの名前は壁で隠れ、近距離でしか出ない |
| 召喚時の演出を一切出さない | 爆発パーティクルとチャイムが「召喚されたMob」だと自己申告する |
| ターゲット追従は `look_at_target` | `look_at_player` だとボット同士の戦闘中もプレイヤーを見つめ続ける |

## わかっている制限

- **盾（シールド）をボットは使いません。** 統合版の盾はスニークで発動しますが、
  Mobがこれを使う挙動をスクリプトから正しく再現できないため、`netherite` キットで
  持たせてはいるものの防御には使いません。
- **ボットはブロックを壊しません。** 設置とクラッチのみです。
- **弓を引くモーションは簡易です。** 矢の弾道・ダメージは正確ですが、
  引き絞りアニメーションはスクリプトからは完全には制御できません。
- **エリトラ、エンダーパール、ポーション投げは未対応です。**
- 見た目はスティーブ固定です。変えたい場合は
  `packs/PvPPracticeRP/entity/pvp_bot.entity.json` の `textures.default` を
  自作テクスチャのパスに差し替えてください（`geometry.humanoid.custom` のままなら
  64×64のスキン画像がそのまま使えます）。
- ボットを大量に出すと処理が重くなります。既定の上限10体は低スペック端末を想定した値です。
